# DSH 插件规范索引

本目录是 `plugins/*` 的规范性依据，供开发者、审核者和 AI 共同使用。DSH 官方协议与 Cordis 生命周期语义优先；本目录负责把仓库内的工程、安全和发布要求变成可执行门禁。

## 规范用语

- `MUST` / `MUST NOT`：硬性要求，不满足不得合并或发布。
- `SHOULD` / `SHOULD NOT`：默认要求；偏离时必须记录理由、风险和替代措施。
- `MAY`：可选做法。
- 每条硬规则有稳定编号。代码审查和交付说明应引用编号，例如 `LIFE-003`。
- 自动检查通过只代表已覆盖的机械规则通过，不代表人工审查完成。

## 冲突优先级

1. 当前版本 DSH/Cordis 官方协议与真实宿主行为；
2. 本目录中的规范；
3. 插件 README 与实现约定；
4. 市场展示字段。

若同级文档冲突，采用权限更小、数据暴露更少、卸载更完整的要求，并在同一变更中消除冲突。不得仅修改文档来掩盖实现不符合宿主协议的问题。

## 完成定义

插件变更只有在下列条件同时满足时才算完成：需求可追溯到实现；清单与实际能力一致；所有已取得资源均可释放；风险相称的测试已新增；`pnpm check` 通过；发版时额外完成最终 `.tgz` 的隔离安装冒烟。无法执行的检查必须明确列出，不能用“应当可用”代替证据。

## 门禁覆盖

`pnpm validate` 机械检查必需文件、包字段、严格类型、脚本、发布白名单、市场兼容性、四类权限、质量声明和内部包状态。架构边界、资源释放是否完整、权限描述是否准确、安全失败语义和真实安装仍需代码审查与测试证明。

修改规范时不得复用或静默改变已有规则编号的含义。新增可机械判断的 `MUST` 时，应在同一变更中更新验证器或说明暂不能自动化的原因。
