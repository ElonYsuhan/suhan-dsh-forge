# 02 架构与生命周期规范

## Host / Client 边界

- **ARCH-001 (MUST)**：文件系统、进程、凭证、持久化和宿主控制能力只在 Host 执行；Client 只通过经声明的宿主服务或 API 使用这些能力。
- **ARCH-002 (MUST)**：跨边界数据必须是可序列化、显式版本化或可向后兼容的 wire contract。不得传递类实例、闭包、Cordis Context、Agent handle、API Key、Cookie 或宿主内部对象。
- **ARCH-003 (MUST)**：跨插件协作通过 Cordis 服务或正式公共契约完成，不得对其他插件做运行时深层导入。仅类型导入也不得制造隐含的发布耦合。
- **ARCH-004 (MUST)**：Client bundle 中共享宿主模块必须 external；新增 external 前必须证明宿主 loader 能解析该精确 specifier，新增 inline 依赖前必须证明它没有共享身份或单例状态。
- **ARCH-005 (SHOULD)**：API 路由使用插件唯一前缀，UI slot、工具名、事件名和样式标记使用稳定命名空间，避免与其他插件冲突。

## Cordis 生命周期

- **LIFE-001 (MUST)**：所有副作用必须归属当前 Cordis 上下文，优先通过 `ctx.effect` 或官方等价机制注册。
- **LIFE-002 (MUST)**：每次注册路由、事件、工具、服务、UI slot、观察器、计时器、Agent handle、文件监听或样式，都必须在同一所有权层记录对应释放动作。
- **LIFE-003 (MUST)**：释放函数必须可重复调用、容忍部分初始化，并等待异步资源真正停止。多个资源并行释放时，单个失败不得阻断其余清理，但错误必须可观测。
- **LIFE-004 (MUST)**：卸载后不得再接收请求、触发回调、推进 Agent、写入数据或遗留插件样式。后台异步流程在写入或调度下一步前必须能识别已卸载/已取消状态。
- **LIFE-005 (MUST)**：初始化中途失败时，已经取得的资源必须回滚；不得留下“只有成功路径才清理”的资源。
- **LIFE-006 (SHOULD)**：资源所有权尽量局部化。全局 Map、缓存或单例如不可避免，必须按实例隔离，并在卸载时清空。

## 状态与并发

- **STATE-001 (MUST)**：持久状态必须定义 schema、默认值、升级策略和损坏数据处理方式。写入应避免产生半文件；多写者场景必须定义串行化或冲突策略。
- **STATE-002 (MUST)**：重试、重复点击、重复事件和宿主重载不得造成重复注册、重复执行或重复提交；有副作用的操作必须定义幂等键、状态前置条件或等价保护。
- **STATE-003 (MUST)**：长任务必须定义取消、超时、失败和恢复语义。不得捕获错误后静默伪装成功。
- **STATE-004 (MUST)**：涉及 Git、文件恢复、删除、归档或进程终止的操作，在执行前验证目标与前置状态；检测到外部变化时停止，禁止覆盖用户或其他任务的工作。

## 生命周期审查表

每个副作用都要能回答：谁创建、谁拥有、何时释放、释放失败如何报告、卸载竞态如何阻止、重复调用会怎样。任一问题无答案，视为 `LIFE-*` 未满足。
