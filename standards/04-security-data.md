# 04 安全与数据规范

## 输入与输出

- **SEC-001 (MUST)**：来自 HTTP、Client、Agent 工具、配置、环境变量和磁盘的数据均视为不可信；在进入业务逻辑前验证类型、长度、枚举、格式和组合约束。
- **SEC-002 (MUST)**：路径先解析到允许根目录，再验证归属；拒绝路径穿越、符号链接逃逸和含糊目标。不得把用户输入直接拼入 shell 命令。
- **SEC-003 (MUST)**：进程调用使用参数数组和明确可执行文件；限制 cwd、参数、运行时间和输出大小。shell 模式默认禁止，确有需要必须专门评审。
- **SEC-004 (MUST)**：HTTP 路由限制方法、body 大小和 content type，返回一致的 4xx/5xx；面向 Client 的错误不得泄露堆栈、凭证、本地绝对路径或内部对象。
- **SEC-005 (MUST)**：渲染用户内容时依赖框架转义；使用 HTML 注入、动态代码执行、`eval` 或 `new Function` 默认禁止。

## 凭证与隐私

- **SEC-006 (MUST)**：凭证由宿主或受支持的 secret provider 持有，不进入源码、清单、日志、timeline、Client 状态、测试快照或持久业务数据。
- **SEC-007 (MUST)**：日志遵循最少披露原则。标识符、请求体、模型输入输出和文件内容仅在排障确需时记录，并先做脱敏和大小限制。
- **SEC-008 (MUST)**：README 说明持久化数据的位置、用途、保留/删除方式和卸载后的处理。删除行为必须区分“卸载插件”和“删除用户数据”，不得默认破坏用户数据。

## 文件、网络与依赖

- **SEC-009 (MUST)**：写文件使用受控目录、最小权限和可恢复写入策略；覆盖或删除前验证精确目标，重要操作提供备份、原子替换或等价恢复手段。
- **SEC-010 (MUST)**：网络请求使用固定或受验证的目标、超时、取消、响应大小限制和安全失败策略；不得把 secrets 转发到未声明目标。
- **SEC-011 (MUST)**：新依赖必须说明用途，检查许可证、维护状态和安装脚本。新增安装脚本依赖默认不允许；人工审查后才能加入根 `allowBuilds`。
- **SEC-012 (SHOULD)**：优先使用平台已有能力和标准库，避免为微小功能引入大依赖或新的供应链面。

## 安全变更的最低证据

新增网络、文件系统、进程或 secrets 能力时，至少提供：权限差异、信任边界、滥用场景、输入拒绝测试、清理/失败测试，以及 `dsh-marketplace.json` 的同步变更。
